# Коннектор 1С (UGE ERP, HTTP-сервисы `hs/aiassistant`) — инструкция администратора

## Что загружается
| 1С | Витрина | Когда |
|---|---|---|
| `/payments` (по каждой организации из `onec.orgs`) | расходование (`fact_cashflow`), статьи, контрагенты | ночью полностью (02:00), днём 10:00, 13:00, 16:00 — инкрементально |
| `/budget` (план) | план платежей по месяцам (`fact_payment_plan`) | то же |
| `/income` | поступления | только если `onec.income_enabled = true` (сейчас 1С отдаёт тестовые данные) |

Остатки по счетам, задолженность, статусы платёжных поручений, платёжный календарь и целевые средства
1С пока не отдаёт (см. `docs/integration/1c-sorov-s1.md`) — в интерфейсе «нет данных».

## Настройка
1. Учётная запись 1С **только на чтение** и адрес сервиса задаются в панели, не в файлах и не в env:
   «Администрирование → Интеграции → 1С: HTTP-сервисы → Изменить» (причина + код 2FA) — адрес
   `https://…/con2026/hs/aiassistant`, лимит ответа (МБ), «Пользователь 1С», «Пароль 1С». Значения
   хранятся зашифрованно, пароль не показывается и не попадает в журнал аудита. Смена адреса стирает
   сохранённые логин и пароль — их нужно ввести заново. Затем «Проверить подключение»
   (`ok` / `auth_failed` / `tls_failed` / `timeout` / `connect_failed` / `http_error` / `format_error`).
2. Файлы и env (только то, что не относится к учётной записи): `secrets/onec_ca_bundle.pem` — корпоративный
   CA (пустой или отсутствующий файл — набор CA certifi (не хранилище ОС), для внутреннего CA нужен PEM; права `root:<gid> 0440`, `scripts/secrets_perms.sh`);
   `deploy/prod.env`: `ONEC_ALLOW_HTTP=true` — только временно, пока 1С не опубликована по HTTPS
   (пароль передаётся открыто; без этого флага адрес `http://` панель не сохранит, а загрузка откажется).
3. Сопоставление организаций 1С и филиалов (коды `UGE-01…UGE-16`) — файл JSON:
   ```json
   [{"branch_code": "UGE-02", "org_uid": "<UID организации в 1С>", "org_name": "Чарвакская ГЭС"}]
   ```
   ```bash
   docker compose -f deploy/compose.prod.yml --env-file deploy/prod.env --env-file deploy/release.env \
     run --rm -v "$PWD/orgs.json:/tmp/orgs.json:ro" worker python -m app.cli onec-orgs --file /tmp/orgs.json
   ```
   Каждое изменение — новая версия настройки и запись в журнале аудита. Без файла команда показывает
   текущее значение.
4. Проверка связи: `… run --rm worker python -m app.cli onec-check` (0 — OK, 1 — 1С недоступна,
   2 — ошибка конфигурации).
5. Задания `etl_onec_full` и `etl_onec_incremental` всегда в расписании worker; пока интеграция «1С»
   не настроена (адрес + логин + пароль), они пропускаются. Расписание — настройки
   `etl.onec_full_cron`, `etl.onec_incremental_cron` (применяется ≤ 60 с без перезапуска).
   Загрузка поступлений (`/income`) выключена: `onec.income_enabled`.

## Ошибки и что делать
| Сообщение в «Состояние обменов» | Причина | Действие |
|---|---|---|
| `тайм-аут`, `HTTP 5xx`, `ConnectError` | 1С недоступна | три повтора (30 с → 2 мин → 8 мин), затем письмо ответственному |
| `доступ запрещён (HTTP 401/403)` | неверная учётная запись | изменить логин/пароль в «Интеграции → 1С» |
| `ответ не JSON`, `неожиданная структура ответа` | 1С вернула HTML/изменила формат | передать текст ошибки разработчику 1С; публикация не выполняется |
| `строк = limit` | данных больше лимита, постраничной выдачи нет | увеличить `onec.page_limit` (≤ 1 000 000) или сузить период; запрос G9 в 1С |
| `Не найден справочник dim_branch: 1C:<название>` | организация 1С не сопоставлена (проверка качества блокирует публикацию) | добавить её в `onec.orgs` (панель «Настройки → 1С» или CLI `onec-orgs`) |
| `Адрес 1С без HTTPS запрещён настройкой сервера` | `http://` при `ONEC_ALLOW_HTTP=false` | опубликовать 1С по HTTPS (или временно `ONEC_ALLOW_HTTP=true`) |

При любой ошибке предыдущая сборка витрины остаётся активной (пользователи видят последние
корректные данные, в верхней панели — время последней успешной загрузки).
