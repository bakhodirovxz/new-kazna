# HR API (hr-api.uzgidro.uz): что использует UGEKAZNA

Раньше здесь был запрос к разработчикам HR на агрегаты по филиалам. Теперь HR публикует
готовый справочник, и запрос снят. Используются только методы чтения (GET) с заголовком
`X-Api-Key`; ключ вводится в «Администрирование → Интеграции» (`hr.api_key`).

| Метод | Что берём |
|---|---|
| `/directory/structure?include_empty=false` | по каждому филиалу (`branches[].id`) — сотрудники по категориям `positions[].category` |
| `/directory/attendance?size=1&include_days=false[&date=ГГГГ-ММ-ДД]` | `statuses`, `summary`, `branches[].by_status` (счётчики по статусам) |

В ответе `/directory/attendance` поле `items` содержит ФИО сотрудников: UGEKAZNA его не читает,
не сохраняет и не пишет в журналы (запрашивается `size=1`). Хранятся только агрегаты, без персональных данных (ФИО, ПИНФЛ, паспорт, телефоны, табельные номера) (ТЗ, раздел 9). Доступ —
только чтение. Подробности настройки — `docs/integration/hr-connector.md`.
