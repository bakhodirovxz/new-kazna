# AI-анализ: поток данных и угрозы (STRIDE)

## Поток
Браузер → (HTTPS, сессия + CSRF) → Caddy → api: `POST /api/v1/ai/analyze {раздел, страница, фильтры,
вопрос|шаблон}` → api собирает сводку из `pub.*` (RLS пользователя) → белый список полей → сканер
(ИНН/ПИНФЛ/счёт/паспорт, ключи ФИО/контрагент/реквизиты; при находке — отказ `ai_context_rejected`)
→ сводка ≤ 14 000 символов + инструкция → (TLS, прокси `EGRESS_PROXY`) → `api.anthropic.com` →
поток ответа → браузер. Ключ API хранится зашифрованным в БД (`core.integration_credentials`,
AAD по имени) и расшифровывается только в процессе `api` в момент запроса; по умолчанию функция
выключена (`ai.enabled = false`).

## Какие данные уходят
Только агрегаты текущей страницы (суммы, доли, названия филиалов, статей, станций, объектов,
кредиторов-банков), сработавшие правила (уровень, заголовок, значение), период, дата данных, вопрос
пользователя (без реквизитов — проверяется). Не уходят: первичные документы и их номера, ФИО,
паспортные данные, ИНН/ПИНФЛ, номера счетов, наименования контрагентов и поставщиков.

## STRIDE
| Угроза | Мера |
|---|---|
| S — подмена пользователя | сессия + TOTP, CSRF на POST, права раздела проверяются сервером |
| T — подмена контекста | контекст строится только на сервере из витрины; клиент передаёт лишь идентификаторы |
| R — отказ от действий | журнал `core.ai_requests` (90 дней) + событие аудита `ai.request` |
| I — утечка данных | белый список + сканер, RLS пользователя, выключено по умолчанию, egress только через прокси |
| D — отказ в обслуживании / расходы | 20/час, 300/сутки, таймаут 60 с, отмена, SDK-повторы выключены |
| E — повышение привилегий | вопрос пользователя и данные помечены как данные, модель не имеет инструментов |

## Остаточные риски
Ответ модели может быть неточным (в интерфейсе — оговорка о рекомендательном характере); условия
хранения данных у провайдера (ZDR) согласуются заказчиком; при необходимости — локальная модель
(предусмотрен интерфейс провайдера `AI_PROVIDER`).
