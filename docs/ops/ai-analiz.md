# AI-анализ — включение, эксплуатация, журнал

**Статус по умолчанию: выключено.** Отправка даже агрегированных финансовых показателей внешнему
провайдеру (Anthropic, США) требует письменного согласования службы информационной безопасности
(требование национальной экспертизы). Без согласования этот раздел не выполняется.

## Как устроено
- Кнопка «AI-анализ» → сервер собирает сводку текущей страницы (только агрегаты, до 14 000 символов,
  без ФИО, ИНН, счетов, паспортов, наименований контрагентов и номеров документов), добавляет
  инструкцию и вызывает модель; ответ идёт потоком (SSE). Браузер модель напрямую не вызывает,
  ключ в браузер не передаётся.
- Модель по умолчанию — `claude-opus-5-5` (настройка `ai.model`, Администрирование → Интеграции →
  «AI-анализ»), официальный Python SDK `anthropic`, таймаут 60 секунд, повторные попытки SDK
  отключены.
- Ограничения: 20 запросов в час на пользователя (`ai.user_per_hour`), 300 в сутки на организацию
  (`ai.org_per_day`); при превышении — сообщение и время следующей попытки.
- Журнал `core.ai_requests`: дата, пользователь, раздел, страница, фильтры, вопрос, длина ответа,
  статус; хранение 90 дней (задача `ai_journal` в worker удаляет старые записи и закрывает
  зависшие). Просмотр — `GET /api/v1/audit/ai-requests` и страница «Журнал AI-анализа» (право
  `audit:read`). В журнале аудита — событие `ai.request` (без текста вопроса).

## Включение (после согласования информационной безопасности)
1. Сетевой доступ: `EGRESS_PROXY` обязателен (без него `api` в prod не запустится; прямой выход —
   только `AI_DIRECT_EGRESS=ack` с правилом `DOCKER-USER`, см. host-hardening). Задать `EGRESS_PROXY` и `AI_BASE_URL` (если нужен шлюз) в `deploy/prod.env`,
   разрешить в прокси только `api.anthropic.com:443` (см. `docs/ops/host-hardening.md`). При TLS-инспекции —
   сертификат ЦС в `deploy/secrets/ai_ca_bundle.pem` (иначе пустой файл).
2. Запуск с оверлеем `compose.ai.yml`: `docker compose -f deploy/compose.prod.yml -f
   deploy/compose.ai.yml --env-file deploy/prod.env up -d api`.
3. Ключ API хранится в панели, не в файле и не в окружении: Администрирование → Интеграции →
   «AI-анализ» → Изменить (причина + код 2FA) → поле «Ключ API». Затем «Проверить подключение» (работает только при включённом `ai.enabled`, не чаще раза в минуту).
4. Включить функцию (аудируемое изменение; причина — номер письма ИБ): Администрирование →
   «Политика безопасности» → AI-анализ (`ai.enabled`), либо аварийно с сервера:
   `docker compose … exec api python -m app.cli ai-enable on --reason "Письмо ИБ № … от …"`.
5. Проверка: в интерфейсе появляется кнопка «AI-анализ»; `GET /api/v1/ai/status` → `enabled: true`.

«AI выключен» = `ai.enabled` выключен ИЛИ ключ не задан.

## Выключение и ротация ключа
- Выключить: `python -m app.cli ai-enable off --reason "…"` или в панели (кнопка исчезает сразу).
- Ротация ключа: в панели заменить «Ключ API» (следующий запрос использует новый ключ, перезапуск
  не нужен), старый ключ отозвать в консоли Anthropic.
- Полное отключение сети: запускать без `compose.ai.yml`.

## Смена модели
Настройка `ai.model` (идентификатор без суффикса даты) в панели; вступает в силу сразу.
Изменение модели согласуется с ИБ так же, как включение.
