# Классификация данных

## 1. Классы

| Класс | Определение | Пример |
|---|---|---|
| К1 — критичные секреты | компрометация даёт доступ ко всем данным | KEK, DEK, pepper, ключ blind index, пароли ролей СУБД, пароль репозитория копий, закрытый ключ TLS |
| К2 — персональные и конфиденциальные сведения | ПДн пользователей, аутентификаторы, реквизиты | ФИО, логин, IP, User-Agent, секрет TOTP, хеши паролей, ИНН контрагентов, номера счетов |
| К3 — служебная финансовая информация | данные учёта и расчётные показатели | факты и агрегаты витрины, планы платежей, допущения финмодели |
| К4 — внутренняя справочная | справочники без ПДн | филиалы, статьи ПКМ № 54, меню, периоды |

Раздел «Кадры» содержит только агрегаты по филиалам и категориям без ФИО и других ПДн работников
(ТЗ, раздел 9; `dwh.dim_position` — без персональных полей).

## 2. Элементы данных

| Данные | Где | Класс | Защита при хранении | Доступ | Срок хранения |
|---|---|---|---|---|---|
| KEK | Docker secret `master_kek` | К1 | файл 0440 на LUKS2, копия в сейфе | api, worker, migrate | весь срок + копии (key-management, П2) |
| DEK | `core.crypto_keys.wrapped_key` | К1 | AES-KW (KEK) | через KEK | до вывода из обращения (`audit_meta`, `audit_chain` — не выводятся) |
| Pepper, ключ blind index, пароли ролей | Docker secrets | К1 | файл 0440 на LUKS2 | по контейнерам | до смены |
| Пароль пользователя | `core.users.password_hash`, `core.password_history` | К2 | Argon2id | только сравнение | история — 5 последних паролей, включая текущий |
| Секрет TOTP | `core.users.totp_secret_enc` | К2 | AES-256-GCM (`mfa`) | при проверке кода | до сброса 2FA |
| Незавершённое подключение 2FA | `core.mfa_challenges` (`token_hmac`, `pending_secret_enc`) | К2 | HMAC-SHA256(pepper); секрет AES-256-GCM (`mfa`) | только сравнение / при подтверждении кода | 5 минут жизни; удаляется через 1 сутки после истечения |
| Резервные коды | `core.backup_codes.code_hmac` | К2 | HMAC-SHA256(pepper) | только сравнение | до использования / перевыпуска |
| Токен сессии | `core.sessions.token_hmac` | К2 | HMAC-SHA256(pepper) | только сравнение | удаляется через 30 дней после окончания или отзыва сессии |
| IP сеанса | `core.sessions.ip_enc` | К2 | AES-256-GCM (`pii`) | владелец сеанса | вместе с сессией |
| ФИО и логин пользователя | `core.users` | К2 | LUKS2, RBAC (`admin:users`) | администраторы | срок работы + блокировка |
| IP и User-Agent в аудите | `core.audit_log.ip_enc`, `ua_enc` | К2 | AES-256-GCM (`audit_meta`) | `audit:read` (User-Agent интерфейсом не выдаётся) | ≥ 12 месяцев (`retention.audit_months`, 12–120) |
| ИНН контрагента | `dwh.dim_counterparty.inn_enc`, `inn_bidx` | К2 | AES-256-GCM (`pii`) + blind index | только `ugk_etl` (загрузка) и `ugk_migrator` (ротация); приложению (`ugk_app`), `pub` и интерфейсу недоступны | бессрочно: записи справочника не удаляются (ретенция удаляет только партиции фактов); удаление или обезличивание неиспользуемых записей по сроку — запланировано |
| Номер банковского счёта | `dwh.dim_bank.account_enc`, `account_bidx` | К2 | AES-256-GCM (`bank`) + blind index | только `ugk_etl` и `ugk_migrator`; приложению, `pub` и интерфейсу недоступны | бессрочно (см. выше); удаление или обезличивание — запланировано |
| Учётные данные интеграций | `core.integration_credentials.value_enc` | К1 | AES-256-GCM (`integration_creds`), только запись через API | worker, api (при использовании) | до смены или удаления в панели |
| Факты витрины | `dwh.fact_*` | К3 | LUKS2, RLS | `ugk_etl`; `ugk_app` — нет прямого доступа | 5 лет (`retention.fact_years`, 5–10): партиции старше срока удаляются |
| Агрегаты | `mart.agg_*`, представления `pub.*` | К3 | LUKS2, RLS | по разделам и области | хранятся сборки витрины (`builds.keep`, по умолчанию 3); отдельный срок не задан |
| Промежуточные загрузки | `stg.rows` | К3 | LUKS2; чувствительные поля шифруются до записи | `ugk_etl` | 7 дней |
| Журнал аудита | `core.audit_log` | К2/К3 | HMAC-цепочка, шифрование IP/UA | `audit:read` | ≥ 12 месяцев |
| Журналы контейнеров | Docker json-file | К2/К3 | ключи полей с секретами маскируются по имени поля; журнал Caddy содержит IP клиента (К2) и URI запроса, заголовки `Cookie` и `Authorization` скрыты | администраторы ОС | 5 × 20 МБ на контейнер |
| Резервные копии | репозиторий pgBackRest | К1–К3 | AES-256 + отдельный диск (LUKS2 — требование к серверу) | backup, хранители | 14 полных копий (и 12 разностных) |
| Кэш | Redis (в памяти) | К3 | внутренняя сеть, пароль, ключ с областью данных | api | 1 час, без сохранения на диск |
| Справочники | `dwh.dim_branch`, `dwh.dim_item` | К4 | RBAC | пользователи | постоянно |

## 3. Требования по классам

| Класс | Хранение | Передача | Журналирование | Уничтожение |
|---|---|---|---|---|
| К1 | только Docker secrets / обёрнуто; никогда в коде, образах, переменных окружения, журналах | в открытом виде не передаётся (пароли СУБД — только через SCRAM); копия в сейф — на носителе | операции — в журнале аудита | `shred`, криптоуничтожение (retire) |
| К2 | шифрование полей или необратимое хеширование; LUKS2 | TLS | значения маскируются | удаление по сроку, криптоуничтожение |
| К3 | LUKS2, RLS, резервные копии зашифрованы | TLS | доступ фиксируется в журнале доступа, выгрузки — в аудите (по мере появления выгрузок разделов) | удаление партиций по сроку |
| К4 | стандартно | TLS | — | — |

## 4. Передача данных во внешние сервисы (Telegram) — минимизация

Правило A-S2.R1: Telegram — внешний облачный сервис без сквозного шифрования, получатели (чаты) не
привязаны к пользователям, ролям и областям филиалов. Поэтому передача **выключена по умолчанию** и
включается только после письменного согласия заказчика / ЦСК на передачу указанных данных:

| Настройка (Администрирование → Интеграции → Telegram-бот) | Значение по умолчанию | Что уходит наружу |
|---|---|---|
| `telegram.summary_scope` | `off` | `off` — ничего; `org_totals` — только итоги по организации (остаток, поступления и расходование с начала месяца, платежи на 14 дней, кредитный портфель и ближайший платёж, курсы USD/EUR, **количество** сработавших правил). Строк по филиалам, наименований контрагентов, номеров счетов, ИНН и названий правил нет |
| `telegram.forward_alerts` | выключено | оповещения о сбоях загрузок и проверок — только заголовок (без сумм, филиалов, контрагентов) |

Изменение этих настроек и токена бота требует права `admin:integrations`, причины и кода 2FA; каждая
отправка сводки записывается в журнал аудита (`notify.telegram.summary`). До получения письменного
согласия оставьте `off`.
